# Data dictionary

## Raw extracts (`data/raw`)

Generated by `scripts/generate_raw_data.py` with seed 42. Loaded into DuckDB schema `raw` as all-varchar, then typed in staging.

| Table | Grain | Notes |
| --- | --- | --- |
| raw_claim_headers | one row per extract copy of a claim | Duplicate reloads, mixed dates, status aliases |
| raw_claim_lines | one row per claim line | CPT-like synthetic codes prefixed `PRC-` |
| raw_claim_events | one row per lifecycle event | Extra intake events exist with new event IDs |
| raw_providers | one row per provider | Specialty blank on a subset |
| raw_members | one row per member | Age band and region only; no names or DOB |
| raw_denial_codes | one row per reason code | CARC-style labels for a synthetic payer |
| raw_payers | one row per payer | Six contracts |

## Staging

| Model | Grain | What it fixes |
| --- | --- | --- |
| stg_claim_headers | claim_id | Trim IDs, parse mixed dates, map status, keep latest ingest_ts |
| stg_claim_lines | line_id | Types and amounts |
| stg_claim_events | event_id | Map event type; flag exact duplicate (claim, type, timestamp) |
| stg_providers | provider_id | Missing specialty flag |
| stg_members | member_id | Typed enrollment date |
| stg_denial_codes | denial_reason_code | Boolean flags |
| stg_payers | payer_id | Names and types |

## Status and event values

Canonical claim status: `submitted`, `in_review`, `pended`, `approved`, `denied`, `paid`, `voided`.

Canonical events: `claim_submitted`, `claim_received`, `claim_pended`, `additional_info_requested`, `claim_denied`, `claim_approved`, `claim_resubmitted`, `payment_issued`, `payment_adjusted`, `claim_voided`.

Crosswalks: `seeds/status_crosswalk.csv`, `seeds/event_type_crosswalk.csv`.
